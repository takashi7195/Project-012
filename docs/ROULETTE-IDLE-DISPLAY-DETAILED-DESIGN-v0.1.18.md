# v0.1.18 ルーレット待機表示 詳細設計書

作成日: 2026-09-25 JST
状態: 実装前設計
関連基本設計: [ルーレット待機表示 基本設計書](ROULETTE-IDLE-DISPLAY-BASIC-DESIGN-v0.1.18.md)

## 1. 対象症状

会場・レースの選択変更に伴い既存処理が予想表示をクリアした際、本命ルーレットの3枠も空になる。待機表示だけを初期数字へ戻し、古い予想結果を残さずに空欄を解消する。

## 2. 状態と表示

| 状態 | 本命ルーレット表示 | 意味 |
|---|---|---|
| 初回表示 | `1`・`2`・`3` | 待機用の初期表示。予想ではない |
| 会場選択後、レース未選択 | `1`・`2`・`3` | 待機用の初期表示。予想ではない |
| 会場・レース選択後、START前 | `1`・`2`・`3` | 待機用の初期表示。予想ではない |
| 既存ロジックの取得中・回転中 | 現行挙動 | 本設計では変更しない |
| 予想成功後 | 現行の確定結果 | deterministic predictionの結果 |

選択変更時には既存の予想データクリア処理を維持したうえで、本命ルーレットの表示値のみ待機用初期数字へ戻す。初期数字をprediction object、main pick、保存データ、API requestへ書き込まない。

## 3. 実装方針

既存の初期化・選択変更処理が本命ルーレットの表示値を空文字または空状態にしている箇所を確認する。該当表示を既存3枠へ「1」「2」「3」と設定する表示専用処理に置き換える。すでに初期化関数がある場合はそこへ集約し、会場選択・レース選択の両方から同じ処理を呼ぶ。

DOM構造、CSS、クラス、style属性、レイアウト値、色、透明度、文字サイズは変更しない。会場・レース選択処理、START enable条件、締切確認、API、予想計算、対抗・穴・narrativeの処理には手を加えない。

## 4. 回帰テスト

既存のUIテスト方式に合わせ、少なくとも以下を確認する。

1. 初回待機状態の3枠が順に`1`、`2`、`3`となる。
2. 会場選択後に3枠が空欄にならず、`1`、`2`、`3`へ戻る。
3. レース選択後に3枠が空欄にならず、`1`、`2`、`3`へ戻る。
4. 以前の予想値が表示されていた後に選択変更すると、古い値ではなく待機数字になる。
5. 待機数字だけではSTARTが有効にならない。
6. 実際の予想結果を渡すと、既存ルーレットが予想結果を表示する。
7. 会場・レース選択欄のDOM・CSS仕様が変わっていない。
