## 設計へ反映する発見

1. `programs.stadiums.<場>.races.<R>` に出走表、`preview`、`result`がある。キーと内部の日付/場/Rの一致を検査する。
2. 未確定の結果にも6枠のnull値と7賭式の空配列がある。オブジェクトの存在だけで「結果あり」にしない。
3. 最近のJSONには公開スキーマ表にない `preview.racers.*.propeller`、`parts`、`result.remarks`、`refunds`、`payouts.*[].label` がある。既知の列だけ保存すると情報を失う。
4. `refunds` は対象枠の配列を観測（9月19日戸田9Rで `[3,4,5,6]`）。過去日のキー不存在と空配列を区別する。
5. `combination: null, amount: 70, label: "特払"`、`amount: 100, label: "不成立"` を観測。金額は有効でも通常の的中組み合わせではない。
6. 着順の `place_number` に7・8・9・10・13・14・16等を観測。`place_number_source` の妨・エ・転・落・失・F・欠等も保持する。1〜6の順位列とは分離する。
7. STには `F.03` と数値 `-0.03` がある。0未満をエラーにしない。展示STと本番STは別項目。
8. `closed_at` は締切時刻。発走時刻ではない。タイムゾーンのない元文字列はJSTとして変換し元文字列も保持する。
9. `entry_number` は枠番、出走表の `boat_number` はボート機材番号。異なる列名を使う。
10. 年齢・級別・各成績は出走表のその時点の値。後日最新の選手属性で上書きしない。
11. 今回の全項目走査で性別・投票前オッズの専用項目は見つからなかった。名前・体重・レース名から補完しない。
12. JSONに提供元の更新時刻は観測できなかった。HTTP Last-ModifiedはJSONファイルの時刻であり個々の情報の公開/確定時刻ではない。

## 証跡

- [集計JSON](RACE-API-OBSERVATIONS-20260920.json): URL、取得時刻、HTTPヘッダー、SHA-256、全日付の項目キー集合、特殊例を記録。
- 生レスポンスはローカル `C:/codex/project-012/research/v0.1.11-api-20260920/` に保存。各日付 `.json`。Git対象外の作業証跡であり、将来のクラウドDBではない。
- SHA-256はUTF-8本文ファイルに対する値。JSONの再整形では一致しなくなる。
- 元JSONの意味的復元試験には別途、キー順を正規化したハッシュを用いる。数値・文字列・null・空配列を同一視しない。
