# UIコンパクト化 試験仕様書 v0.1.21

作成: 2026-10-01 JST。対象: 設計に従った実装後の確認。

## 環境と方法

主基準375×667、追加320×667・390×844・430×932・768×1024・1280×800。Edgeで現在UIの保存値と実装を比較し、可能な環境でWebKitも確認する。APIはローカルのモックを使う。合成データを実レース結果として扱わない。

| ID | 試験 | 合格条件 |
|---|---|---|
| C01 | 375×667で採用案と寸法比較（実測済み） | 本命白枠331×約186.56px（状態通知なし／解析中）、買い目84.375px角、START約169.94×36px。座標・寸法は同一フォント条件で±1px |
| C02 | 6画面幅で比較 | 現状と白枠の幅・左右端、選択欄幅、買い目寸法が±1px以内で一致。document.scrollWidthがviewportを超えない。数字やタイトルが欠けない |
| C03 | バージョン削除 | 本番index.htmlの表示にv0.1.20および.version要素がなく、状態欄は存在する |
| C04 | 生成前・中・成功 | 会場・レース選択、START操作、回転・停止後の数字、成功時の展開文が既存どおり。START下の状態表示が読める |
| C05 | 生成失敗・締切・再試行 | 既存メッセージがボタン直下の白枠内に全文表示される。再試行開始でメッセージの可視領域がなくなる。長文は折り返し、白枠や次の欄と重ならない。既存の再試行制御を維持 |
| C06 | 対抗・穴・コメント | 枠幅と買い目のサイズを維持。展開文が長い場合もコメント欄と重ならずスクロールできる |
| C07 | 狭幅・Safari回帰 | 320pxの左右12px paddingと、レース選択後・START後の横はみ出し対策を維持。WebKitで横スクロールや縮小を起こさない |
| C08 | 操作性 | Tab/Enterによる操作、フォーカス表示、スマートフォンでのSTARTタップが可能。36pxのボタンで隣接要素を誤操作しないか実機で確認 |
| C09 | 配布識別 | CSSクエリーがv0.1.21-title-centered1、JSクエリーがv0.1.21-compact1。公開指示後にURL上の新画像・CSS配信を確認 |
| C10 | 終了と競合 | 成功・失敗・タイムアウト・中断後にボタンがSTARTへ復帰。旧runの完了で新runの「解析中…」が消えない。選択・再試行・締切の可否は従来どおり |
| C11 | 読み上げ | 解析通知は状態欄のlive regionに保持。視覚上の空行を作らず通知できる。失敗・締切も読み上げられ、視覚表示と一致 |
| C12 | タイトルと透過画像の配置 | 320/375/390/430/768/1280px幅で画像が左上装飾、文字がviewportの水平中央。文字と画像、会場・レース選択欄が重ならず、横スクロールなし |
| C13 | 画像アセットと表示崩れ | 透過画像がローカルHTTPから読み込まれ、円形枠・背景色を持たず自然に表示される。タッチ・セレクト操作を妨げず、見出しの読み上げ順は変わらない |

既存ai-ui-browser-smoke.cjsを生成・失敗・長文回帰に利用する。既存のSafari向け表示確認を再利用し、今回のサイズ比較のみ必要に応じて追加する。実機未確認を自動試験合格と混同しない。公開試験は公開指示後に行う。
