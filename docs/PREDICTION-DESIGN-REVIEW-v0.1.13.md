## 1. 結論

主要な要件から基本・詳細設計を作成できたが、従来の「採点基準はほぼ全て確定」という説明は強すぎた。ヒアリング記録には矛盾、具体値未定、API事実との不一致がある。本レビューでこれらを明示し、必要な項目をユーザーに再確認した。

**レビュー版の文書完成と、実装着手可能な確定版は異なる。** 未決事項を解決するまで、未決の採点ロジックを実装しない。

## v0.1.14実装範囲の確定

100点の最終設計は変更しない。v0.1.14の実装済み基本最大配点は66点（コース18、能力6、モーター14、平均ST9.6、展示タイム6.6、展示ST4.8、級別5、ボート2）とする。艇ごとの欠損は`effectiveMaximum`から除外し、最終点を100点換算する。

残る34点（コース別成績16、直近10走3、今節成績4、会場・風・波7、体重・整備1、F/L信頼性2.4、チルト0.6）は次版へ送る。うち23点はDBに基礎データがあっても、集計期間、最低母数、異常結果の扱い、節ID、正式得点率が未確定である。根拠が未確定の項目を推測で採点しない。

## 2. 発見した問題と解決方法

| 問題 | 影響 | 整理・修正 |
|---|---|---|
| 全国/当地の採点枠が100点表から消えた | 9点を直近専用にすると合意した勝率評価を置けない | 今回合意で全国/当地6点＋直近3点へ |
| 補正表なしの風・波・チルト・体重・整備 | 実装者の推測で点数が決まる | ユーザー合意：表確定まで採点除外、原値は保存 |
| 部品交換はAPIにないという説明 | 利用可能な情報を誤分類 | 保存実JSONのparts実値を確認。取得可・採点未定へ修正 |
| 本番進入と展示進入が曖昧 | 締切前に知れない情報を利用 | 現レースは展示進入又は枠。結果進入は過去集計だけ |
| 着順から正式今節得点率を算出する | 減点・特別配点・節の区切りを再現できない | 公式配点根拠がなければ平均着順へ、節不明は除外 |
| API上流更新時刻がある前提 | 古い情報を新しいと誤認 | checked_at/file_last_modified/source_updated_atを別管理 |
| 型付きDB列が未充填 | 全欠損や締切不明 | 同じ版のraw_jsonとclosed_at_sourceを検証して読む |
| スナップショット不変と文章再試行が衝突 | 成功に更新すると元の失敗履歴を失う | 計算本体は不変、文章試行は追加レコード |
| partial＋gemini_errorを単一状態で扱う | 欠損情報を失う | calculation_statusとnarrative statusを分離 |
| 取得時刻を入力ハッシュへ混ぜる | 5分ごとに無意味な再生成 | 内容hashと取得観測を分離し、鮮度は毎回検査 |
| 後日結果を使う過去10走計算 | バックテストが未来情報を含む | as-of観測版と履歴証拠を固定 |
| 同値の相対項目に枠番順位を付ける | 同じタイムなのに点差が出る | 平均順位点の技術案を明記 |
| 展示Fを単純に最小STとして扱う | F艇が最速の高得点になる | 別状態として扱い未承認規則で加点しない |
| 率の差分後に合計100へ正規化 | 4〜6着を消して成績を水増し | 排他的1〜3着率を保持、丸め補正以外の再正規化禁止 |
| 予想の得点・母数差を公平と断定 | 少数情報だけの艇が高得点に見える | 有効満点・母数を記録し不確実性を明示 |

## 4. 見落としてはいけない限界

- 直近30日DBがあっても、全選手について10走や同コース5走を保証しない。最新の全出走歴である証明も収集カバレッジ次第。
- 今節と直近10走は期間的に重なる場合がある。別の指標として扱うことと、統計的な重複がゼロであることは異なる。
- コース・コース別成績、全国/当地・級別も相関がある。二重評価を完全解消したとは表現しない。
- 高い総合点をそのまま3連単の着順に対応させる方法は、着順別確率モデルではない。本命・対抗の順序は合意したルールであり最適性は未検証。
- 入力固定で数字は再現できるが、Geminiの表現まで同じになる保証はない。再利用と文章検証で制御する。
- 予想を削除しない方針は無料枠で永久保存できる保証ではない。容量実測前に無期限の収容能力を約束しない。
- 取得鮮度10分/30分は提供元の実際の更新遅延を保証しない。
