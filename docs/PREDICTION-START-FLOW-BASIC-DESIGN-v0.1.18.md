# v0.1.18 START・予想表示フロー 基本設計書

- 作成日: 2026-09-25 JST
- 状態: ヒアリング確定内容を反映した実装前設計
- 対象ブランチ: `dev/v0.1.18`
- 関連資料: [詳細設計書](PREDICTION-START-FLOW-DETAILED-DESIGN-v0.1.18.md)

## 1. 目的と対象

次の2課題をまとめて改善する。

- ④ 会場・レース選択後のSTART有効化遅延と、処理中・操作不可理由の分かりにくさ。
- ⑤ 本命ルーレットの回転中に対抗・穴が先に表示される問題。

START直後に回転を開始し、その間に既存予想APIの処理を進める。結果はサーバーで確定したものを使用し、回転によって予想を決めない。

本設計書の作成は実装・公開完了を意味しない。

## 2. 現状と確認された問題

- レース選択のchange処理でSTART可否を再計算していない。ローカル再現では、開催情報取得済み・締切前レース選択済みでもSTARTが無効のまま残り、60秒の定期判定相当の処理で有効になった。
- START後はAPIの応答を待ってから回転を開始している。待機と回転が直列になっている。
- 対抗・穴・レース展開は回転開始前に描画される。
- 定期更新の操作可否計算が処理中状態を考慮せず、処理途中でSTARTや選択欄を有効化し得る。
- 現状の停止処理は、3秒待機＋減速、停止後6秒待機＋減速、停止後9秒待機＋減速を順次実行する。

約30秒の操作待ちという利用者の報告と、最初の不具合は整合する。ただし、本番の待ち時間すべての原因を測定・確定したものではない。開催情報取得APIの性能改善は今回の対象外とする。

## 3. 確定した操作フロー

1. 初期表示は「会場」「レース」未選択、本命は待機表示の「1・2・3」。
2. 当日JSTの開催情報と現在時刻で、有効な会場・レースを利用者が選ぶ。
3. 選択変更時に即座に締切・START可否を再判定する。60秒更新を待たせず、予想APIも先行実行しない。
4. STARTを押すと前回結果を消し、全リールの回転と予想API処理を同時に開始する。
5. STARTから最初の3秒が経過し、かつ有効な予想結果が取得できたら、1つ目の減速停止を開始する。
6. 1つ目の停止完了から6秒後に2つ目を減速停止する。
7. 2つ目の停止完了から9秒後に3つ目を減速停止する。
8. 本命の全リール停止から0.5秒後に、対抗・穴・レース展開をまとめて表示する。
9. 操作制限を解除し、その時点の開催日・締切で再実行可否を判定する。

本命は各リールが停止した数字で表示する。0.5秒後まで本命を隠す仕様ではない。停止順・減速方法・回転速度は現行を維持する。

## 4. 時間の契約

| 項目 | 確定仕様 |
|---|---|
| 最初の待機 | STARTから3秒。API取得待ちと並行 |
| 1つ目の減速開始 | 3秒経過と有効な結果取得の両方が完了した時点 |
| 2つ目の減速開始 | 1つ目の停止完了から6秒後 |
| 3つ目の減速開始 | 2つ目の停止完了から9秒後 |
| 対抗・穴・展開表示 | 全停止から0.5秒後 |
| API取得上限 | STARTから60秒。取得後の停止演出と0.5秒を含めない |

APIが早く返っても停止演出は短縮しない。3秒より遅い場合は最初の回転を延長して待つ。取得に失敗した場合は3秒や停止演出の完了を待たずに回転を中止する。

結果表示までの目安は `max(3秒, API取得時間) + 各リールの減速時間合計 + 6秒 + 9秒 + 0.5秒`。APIの60秒は画面全体の所要時間上限ではない。従来の直列処理から重ねられる時間は最大3秒であり、大幅な処理高速化を約束しない。

HTTP 202 generatingは失敗ではなく待機状態。既存のretryAfterと最大リクエスト数5回を維持し、60秒以内で再確認する。回数上限に先に達した場合は60秒を待たず取得失敗として終了する。

## 5. 文言・表示位置・見た目

| 状況 | 表示文言 | 場所 |
|---|---|---|
| START後の処理・演出中 | レース解析中… | START直下 |
| 通信失敗・取得失敗・タイムアウト | 解析できませんでした | START直下 |
| 選択中レースの締切・APIの締切拒否 | このレースは締切です | START直下 |
| 予想成功・レース展開文のみ失敗 | レース展開を生成できませんでした | レース展開欄 |

- STARTの文字は常に「START」。生成中・取得中等に変更しない。
- START直下に状態表示用の高さを常時確保する。メッセージ表示・消去による上下移動を防ぐ。
- 正常完了時は処理中メッセージを消す。完了時点で締切済みなら締切メッセージを表示する。
- メッセージはテキストとして表示し、技術的な例外・APIエラー本文をそのまま表示しない。
- 既存の会場・レース欄、ルーレット、ボタンの幅・色・文字の太さを変えない。新設領域の常時確保に必要な縦方向の追加のみ許容する。
- 展開文の`white-space: pre-line`、段落間空行、textContentによる安全な表示を維持する。

初回の開催情報ロードや5分更新の取得頻度・独立したローディング文言の追加は、この確定文言の対象に含めない。STARTが無効な間に予想を先行生成することもしない。

## 6. 処理中の操作と前回結果

STARTから全停止＋0.5秒後の結果表示完了まで、会場選択・レース選択・STARTを無効にする。エラー時はその時点で制限を解除する。定期更新もこの制限を上書きできない。

START時に前回の本命・対抗・穴・展開文をクリアする。新しいAPI結果は演出完了まで内部で保持し、対抗・穴・展開を先に描画しない。穴がnullの場合は既存の未表示表現とし、前回の穴を残さない。

## 7. エラー・締切時の復帰

| 状況 | 選択状態 | 表示・次の操作 |
|---|---|---|
| 通信失敗等で、選択中レースがまだ有効 | 会場・レースを維持 | 回転を中止し1・2・3へ戻す。失敗文言を表示。STARTで手動再試行可能 |
| 締切済みで、同じ会場に他の締切前レースあり | 会場を維持、レースを解除 | 1・2・3、締切文言、START無効 |
| 会場の全レースが締切済み | 会場・レースを解除 | 1・2・3、締切文言、START無効 |
| 締切情報が不明・不正、対象日が不一致 | 安全に確認できない選択を解除 | 推測でSTARTを有効にしない。取得失敗と締切確定を区別する |
| 展開文だけ失敗 | 数値予想を通常どおり表示 | 回転は正常停止。展開欄のみ失敗文言 |

ページ全体は再読み込みしない。別会場・次レースへ自動移動しない。有効な選択を利用者が行った時点で前のエラー・締切メッセージを消す。通信失敗の自動やり直しは行わず、利用者のSTART操作を待つ。202の再確認はこの手動再試行とは別扱い。

## 8. 定期更新と正常取得済み結果

- 60秒の締切判定、5分の開催情報再取得、JST日付切替は維持する。
- 処理中の定期更新は操作を解禁しない。実行対象の会場・日付・レースを途中で差し替えない。
- 正常取得した予想は、演出中に締切を迎えても最後まで表示する。表示後に締切を再確認し、再実行は禁止する。
- 正常完了した結果は定期更新や締切到来だけでは消さない。必要な選択解除と、表示結果を消す処理を分離する。
- 結果は利用者が別の会場・レースを選ぶか、再度STARTを押すまで保持する。自動的な選択解除後も、内部では表示結果の対象レースを保持し、別レースの結果として再利用しない。
- APIが締切済みとして拒否した場合は正常取得ではないため、前節の締切復帰を行う。

## 9. 変更範囲と保護対象

実装対象はフロントエンドの状態制御・API待機制御・描画タイミングと、その回帰テスト。必要なフロント側のエラー分類を含む。既存APIの契約・処理順序は変更しない。

変更しないもの: ①〜③で確定した仕様、会場順、レース順とラベル、scoring、本命・対抗・穴の算出、narrative生成仕様、snapshot reuse・lease、comments、race-ingest、Edge Functions、DB、migration、Secrets、Scheduler。

①〜③の利用者による画面確認は別の残課題として維持する。本設計作成で確認済み扱いにしない。commit・push・公開反映・本番試験は実装後に別途明示指示を受けて行う。

## 10. 受け入れ条件

選択直後のSTART有効化、即時回転、既存停止演出、全停止後0.5秒、60秒タイムアウト、手動再試行、締切リセット、定期更新との競合防止をテストする。対抗・穴の先行表示や旧結果・遅延応答の混入がないことを確認する。

詳細な試験ケースと実装上の境界は詳細設計書に定める。今回は設計書のみを作成し、ソースコード・テスト・既存の作業ファイルを変更しない。
