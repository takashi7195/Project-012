# 本命・対抗・大穴 試験仕様書 v0.1.22

関連: [詳細設計](AI-BET-CATEGORY-DETAILED-DESIGN-v0.1.22.md) / [試験成績書](AI-BET-CATEGORY-TEST-REPORT-v0.1.22.md)

設計変更の段階では実行しない。実装後、下記を確認する。旧「穴」の比較結果は今回の合格証跡に流用しない。

| ID | 確認方法・対象 | 期待結果 |
|---|---|---|
| C01 | 初回および形式修正時の生成プロンプトを確認 | 本命・対抗・大穴の定義が各1回含まれ、`hole`との対応が明示される。旧区分の「穴」定義や同じ3艇を禁止する条件が混在しない。 |
| C02 | 同じレース入力で新旧プロンプトの設定hashと再利用キーを比較 | 新旧で異なる。新指示内では同一入力・同一設定の再利用を維持する。 |
| C03 | 既存出力契約に有効・無効の応答を渡す | 重複艇、範囲外艇、完全一致の買い目、空文章は不正。同じ3艇の着順違いは有効。 |
| C04 | 送信直前の要求をモックで確認 | 追加定義・項目対応が含まれ、レース入力、モデル、スタイル、時間設定に意図しない変更がない。 |
| C05 | 保存済み実レースの入力で実装後の生成を1件実施 | 有効な3点と展開文を生成できる。艇番・選手名・本文で断言したデータを入力と照合し、本命と展開文の整合性を確認。大穴の大きな波乱に入力上の根拠があるか目視評価する。配当・的中率・3艇の構成違いは合格条件にしない。 |
| C06 | Functionとページの公開反映後、再読み込み・新規START | 新指示の生成結果が表示され、旧結果を新規生成の証跡として扱っていない。 |
| C07 | DOMとモック成功応答の表示を確認 | ◎ 本命・○ 対抗・☆ 大穴。読み上げラベルは対抗と大穴の予想／大穴予想。`hole`の配列と大穴行の表示が一致。 |
| C08 | 360px・375px・PC幅で表示を確認。可能ならiPhone SafariとAndroid Chromeも確認 | 大穴が見切れず、横スクロールが増えず、買い目の正方形と既存の枠幅・配置を維持。実機確認とブラウザー上の幅再現を区別して記録。 |

APIキーや認証情報は証跡に含めない。実生成の対象・要求上限を開始前に明示し、実際の要求回数・時間・形式結果・意味上の評価を成績書へ記入する。空応答や通信失敗は失敗として残し、成功したものだけを集計しない。実生成・公開確認に進んでいない段階は未実施とする。
