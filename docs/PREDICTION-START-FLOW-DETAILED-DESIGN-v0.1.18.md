## 1. 現行コードとの対応

| 場所 | 現行処理 | 必要な変更 |
|---|---|---|
| `script.js` 選択change | 会場変更時のみ可否更新。レース変更時は表示クリアのみ | 両方の選択変更で現在時刻を使って可否を再判定 |
| `updateStartAvailability` | 選択肢のdisabled中心の判断 | 実行中・開催情報状態・日付・締切を統合して制御 |
| `applyStadiumAvailability` / `applyRaceAvailability` | 選択無効化時にabort・表示クリア | 選択肢更新と実行中・結果保持の扱いを分離 |
| `loadStadiumAvailability` finally | 会場を無条件で有効化 | 共通制御を呼び、実行中ロックを維持 |
| START click | API取得後に回転、対抗・穴は回転前描画 | 回転とAPI待ちを並行、描画は全停止後0.5秒 |
| `requestPrediction` / `client.mjs` | 202でボタン・展開欄の文言を書き換え | START直下の状態表示へ集約。締切と他エラーを識別 |
| `stopRoulette` | setTimeoutとrequestAnimationFrameで順次停止 | 順序・減速式を維持し、キャンセル時の後続描画を防止 |
| `index.html` / `ui-reference.css` | START直下に専用状態領域なし | 専用領域と限定CSSのみ追加 |

現行`client.mjs`の`displayResult()`は展開失敗時に「レース展開文を生成できませんでした。」を返す。フロント用表示文言のみ、確定した「レース展開を生成できませんでした」へ合わせる。サーバーのnarrative生成・validationは対象外。

## 2. 状態モデル

名前は実装時に既存構成に合わせられるが、次の状態を区別する。

| 状態 | 内容 | 操作 |
|---|---|---|
| idle | 未選択・選択待ち | 有効な選択肢を操作可能。STARTは条件次第 |
| acquiring | 回転しながらAPI取得、または最初の3秒待ち | 全3操作を無効 |
| stopping | 確定した本命で順次減速停止 | 全3操作を無効 |
| revealing | 全停止後の0.5秒待ち | 全3操作を無効 |
| displayed | 結果描画完了 | 現時点の開催情報・締切に従う |
| failed | 取得失敗・タイムアウト後 | 同上。締切前なら手動再試行可能 |

締切・開催情報ロード状態はこの状態とは別に保持する。実行中の判定はacquiring・stopping・revealingの全期間を含む。API応答到着だけでロック解除しない。

実行ごとに次を保持する。

- 単調増加する実行IDと、固定したselector `{ raceDate, stadiumCode, raceNumber }`。
- START時刻（経過時間用の単調時計）とAPI取得期限。
- AbortController、待機タイマー・描画フレームの取消情報。
- 内部の取得済みprediction。対抗・穴・展開文は公開時点まで未描画。
- 表示済み結果のselector。画面の選択状態が自動解除されても結果の所属は保持。

新しい実行IDと一致しない非同期応答・finally・タイマーは画面や操作状態を変更できない。

## 3. START可否と選択イベント

START有効の必要条件は、実行中でないこと、現在のJST日付に対応する利用可能な開催情報があること、利用者が会場とレースを明示選択済みであること、対象レースの有効な締切日時が現在時刻より未来であること。

`option.disabled`だけを信頼せず、保持する`closedAt`を現在時刻と比較する。会場可否は当日締切前レースが1件以上という既存条件を維持する。未知・不正な締切は有効にしない。

- 会場変更: レースを未選択に戻し、既存表示をクリア、1・2・3へ戻し、即時に可否更新。
- レース変更: 現在時刻で再判定、既存表示をクリア、1・2・3へ戻し、即時に可否更新。有効なら60秒更新なしでSTART有効。
- START押下: 実行中なら何もしない。最新時刻で再確認し、無効なら予想POSTを送信しない。
- 選択が有効になったときは前のエラー・締切メッセージを消す。

操作disabledの設定は共通関数へ集約する。実行中ロックが最優先であり、開催情報取得のfinally、60秒更新、5分更新のどこからも上書きしない。初回ロード・更新中の既存安全制御は維持し、処理完了後も情報不明なら無理にSTARTを有効にしない。

## 4. 回転と非同期処理の順序

START時に実行ID・selector・時刻を固定し、前回結果を消す。リールを再構築して現行の回転クラスを付け、「レース解析中…」を表示する。ネットワーク応答を待たずに回転を開始する。

同時に、最初の3秒の経過待ちと予想取得を開始する。以下は処理順序を示す擬似コードであり実装ではない。

```text
開始時刻・実行ID・selectorを固定
操作をロック → 前回表示を消去 → 回転開始
並行して開始:
  STARTから3秒の待機
  STARTから60秒を上限に予想取得
両方成功:
  右リールを減速停止（追加の3秒待機はしない）
  右停止から6秒待機 → 中リールを減速停止
  中停止から9秒待機 → 左リールを減速停止
  全停止から0.5秒待機
  対抗・穴・レース展開を描画
  状態表示・選択肢・操作可否を再評価
いずれか失敗:
  待機・回転を中止 → エラー復帰
```

`slots`の現行順は`[slot-3, slot-2, slot-1]`。それぞれ`prediction.main[2]`、`[1]`、`[0]`で停止する。既存の毎秒6艇分の速度・等減速式・位置補正を維持する。

1つ目の停止をAPI応答後にさらに3秒遅らせない。2つ目・3つ目の6秒・9秒は、STARTからの絶対時刻に変更しない。

最初の3秒未満で失敗した場合も即時復帰する。APIが正常完了したら60秒の取得タイマーを解除し、その後の減速や0.5秒待ちをタイムアウトさせない。

## 5. API待機・失敗分類

既存の`POST predictions`と`pollPrediction`を使う。selectorは実行中の選択欄から再取得せず固定値を使う。動的importや準備処理の時間も含め、取得期限はSTARTから60,000msとする。内部pollingに残時間を渡す等により、期限が二重に延長されないようにする。

| 応答・事象 | フロント側の扱い |
|---|---|
| HTTP 200かつ既存条件を満たす予想 | 有効な結果取得。mainを停止先として保持 |
| HTTP 202 / status=generating | main等を参照せず待機。retryAfterに従う |
| status=closed | 締切拒否。締切文言と選択リセット |
| status=stale、HTTPエラー、取得・解析失敗 | 取得失敗。「解析できませんでした」 |
| deadline_unavailable | 締切不明。締切確定と偽らず取得失敗扱い |
| 60秒経過、既存最大5回の確認上限到達 | 取得を打ち切り、取得失敗表示 |
| 有効な予想でnarrativeのみ失敗・null | 数値予想の成功を維持。展開欄のみ失敗文言 |

最大5回のPOSTは202後の既存確認を含めた総数。通信エラー・非202エラーの自動再送や、表示上の失敗からの自動STARTは追加しない。

締切とその他エラーはフロント内部のcode等で識別し、表示文字列への部分一致に依存しない。必要なら`client.mjs`のエラーに安全な分類を付けるが、サーバー契約は変えない。HTTP 200だけで成功扱いにしない。

AbortSignalをfetchと待機へ伝播する。タイムアウト後にサーバー処理自体が継続する可能性はあるため、クライアント中止をDB処理取消とは扱わない。遅延応答を実行ID・状態・期限でも排除する。再試行は既存snapshot reuseに任せ、snapshotの削除・再生成操作は追加しない。

## 6. 表示とエラー復帰

STARTの直後、version表示の前に状態表示専用要素（例: `prediction-status`）を置く。`role="status"`、`aria-live="polite"`等により状態変化を通知する。文言はtextContentで設定する。

最長の確定文言をスマホでも表示できる高さを初期から確保する。文言が空でも領域を除去しない。必要な専用CSSだけを追加し、既存selectors・slot・STARTの幅、色、文字の太さ、余白指定を書き換えない。新設領域分の縦方向の増加と、メッセージ切替時のレイアウト移動を区別して検証する。

処理中は「レース解析中…」、通常完了時は空文字。取得失敗時は「解析できませんでした」、締切確定時は「このレースは締切です」。展開文だけの失敗は展開欄に「レース展開を生成できませんでした」。STARTラベルは不変。

取得失敗時は全タイマー・フレームを停止し、回転クラスを外して待機1・2・3へ戻す。前回の対抗・穴・展開を復活させない。開催情報上まだ有効なら両選択を維持し、ロック解除後STARTで手動再試行できる。

締切拒否または失敗時点で締切を確認できた場合は、レースを解除する。同会場に残りレースがなければ会場も解除する。APIがclosedを返した対象を、古いローカルキャッシュだけで直ちに再度有効にしない。対象日・会場・レースに限定した拒否状態を保持する等で再選択を防ぐ。

情報欠損・対象日不一致も安全側に無効とするが、確認できていない締切を断定しない。別レースの自動選択やページ再読み込みは行わない。

## 7. 定期更新・日付変更との競合制御

60秒ごとの締切再判定と5分ごとの開催情報取得は継続する。予想実行中も開催情報は更新できるが、現在実行のselector、操作ロック、描画途中のリールを更新処理が直接変更しない。

- acquiring中: 選択肢更新だけで実行をabortしない。固定対象へのAPI結果または60秒上限を待つ。サーバーの締切判定がclosedなら復帰する。
- 正常応答後のstopping/revealing中: 締切到来・日付変更を理由に中断しない。取得済みの本命で最後まで停止する。
- displayed: 最新の選択可否は再判定するが、成功結果は消さない。自動選択解除と`clearPredictionDisplay`を直結させない。
- failed/idle: 締切済みの選択を解除し、待機表示・START不可へ整合させる。

正常終了時に締切を迎えていた場合、同会場に残りがあればレースのみ、なければ会場も解除し、STARTを無効にする。ただし成功した本命・対抗・穴・展開は保持する。これは失敗時の1・2・3復帰とは別経路。

JST日付は既存の`formatJstDate`、締切はタイムゾーン付き`closedAt`で比較する。前日データを新しい当日レースの選択根拠にしない。異なる日付の取得応答や古い実行応答が後着しても、新しい状態を上書きさせない。頻度変更・新しい外部API・DB問い合わせ最適化は今回行わない。

サーバー側・scoring・narrative生成・comments・race-ingestの変更を前提としない。今回の設計書作成では上記の実装予定ファイルを変更しない。

## 9. 試験設計

外部APIはstubとし、仮想時計・制御可能なPromise・requestAnimationFrameで時間境界を検証する。本番POSTは行わない。既存UIハーネスのselect.value/selectedIndex、DOM子要素のクリア、クラス・style・イベント挙動がブラウザと一致する範囲を確認し、不足分を補ってから判定する。

| ID | ケース | 期待結果 |
|---|---|---|
| T01 | 情報取得済みで有効な会場→レースを選択 | change直後にSTART有効。60秒経過・追加fetch不要 |
| T02 | 未選択、締切一致・超過、不正日時、別日データ | START無効。勝手に次を選択しない |
| T03 | START直後にAPIを未解決にする | 回転開始・解析中文言・全操作ロック・旧結果消去 |
| T04 | APIが1秒で成功 | 3秒までは減速しない。3秒で1つ目の減速開始 |
| T05 | APIが10秒で成功 | 10秒で1つ目の減速開始。さらに3秒を足さない |
| T06 | 1つ目と2つ目の停止 | 各停止完了を起点に6秒・9秒待つ。停止順とmain値は現行どおり |
| T07 | 本命全停止後499ms/500ms | 前者は副結果未表示、後者で対抗・穴・展開を描画し操作再判定 |
| T08 | hole=null、narrative=null/error | 古い値を残さず、展開欄だけ指定文言。本命等の成功を維持 |
| T09 | API未解決で60秒経過 | 回転停止・1/2/3・失敗文言。有効な選択を維持して再試行可 |
| T10 | 59秒で正常取得、その後60秒経過 | 正常演出を打ち切らない |
| T11 | API準備処理遅延、202継続 | 期限はSTART起点で延長されず、retryAfter・最大5回も遵守 |
| T12 | 最初の3秒内に通信失敗 | 3秒を待たず復帰。自動再START・不要な再POSTなし |
| T13 | タイムアウト後の遅延応答・旧finally | 表示・選択・新実行のロックを書き換えない |
| T14 | API closed、他レースあり/なし | レースのみ/両選択解除、締切文言、START無効、1/2/3 |
| T15 | 失敗後の手動再試行 | 同じ選択で新実行。締切到来ならPOSTせず締切処理 |
| T16 | 各実行状態で60秒・5分更新/取得finally | ロック解除・二重POST・予想の途中クリアなし |
| T17 | 正常取得後に締切到来 | 最後まで演出・結果表示。再実行不可、結果保持 |
| T18 | 結果表示後の定期締切処理と利用者の選択変更 | 前者では結果保持、後者では消去し1/2/3 |
| T19 | JST日付切替・更新応答の前後逆転 | 実行対象不変。前日データで翌日STARTを有効化しない |
| T20 | 全状態の文言・DOM | START文字固定、所定の表示位置、技術エラー露出なし |
| T21 | 数値予想・展開を取得して描画 | 値の再計算・改変なし。textContent/pre-lineと段落維持 |

実装後は関連UI/clientテスト、全Node回帰、`node --check script.js`、`git diff --check`を実行する。全Nodeは対象`*.test.mjs`を明示して実行し、ブラウザ専用・Deno専用ファイルをNodeへ誤投入しない。タイミング系の一時失敗を隠す仕様変更はしない。

ブラウザ確認ではスマホ幅と通常幅で、状態領域の出入りによる位置ずれがないこと、既存欄の幅・色・太さが変わらないこと、回転即時開始、順次停止、0.5秒後表示、エラー停止、再試行を確認する。新設領域による常時の縦寸法追加は比較時に明示する。

## 10. 実装前の確定事項と範囲外

時間・文言・操作制限・再試行・締切復帰・定期更新との関係は本書のとおり確定。新しい状態領域の具体的なCSS値や内部関数名は、既存デザインと試験結果に合わせる実装詳細とする。

バックエンドの24会場検索の性能最適化、開催情報ロード専用文言や独立した取得タイムアウトの追加、narrative別取得方式への変更は本実装へ混ぜない。①〜③の未完了の利用者確認も別管理とする。既存変更・未追跡監査ファイルを保持し、commit/push/deployは別途の明示指示まで行わない。
